# Moroshka Notes

Личная библиотека Markdown для Android и браузера. Напишите мысль, добавьте `[[Название]]` и откройте ссылку, чтобы создать следующую заметку. В разделе связей появится обратный путь. Строки `- [ ]` собираются в общий список задач. Поиск работает по тексту, заголовкам и `#тегам`.

## Попробовать

- **Android 8+**. Скачайте тестовый APK из [релизов](https://github.com/zazzool/moroshka-notes/releases). Заметки сохраняются в приватном каталоге приложения. Импорт и экспорт отдельных файлов доступны через системный выбор документов. Меню «Поделиться» передаёт выбранный текст в другое приложение.
- **Браузер**. Откройте адрес своего сервера или запустите сервер на компьютере. Редактор сохраняет изменения в хранилище этого браузера. После первого открытия по HTTPS или через localhost оболочка кэшируется для офлайн-работы. Очистка данных сайта удаляет локальную копию. Для переноса используйте синхронизацию или экспорт.
- **Обмен между устройствами**. Введите адрес сервера и ключ на Android. В браузере введите ключ через «Подключение». Кнопка «Синхронизировать» отправляет локальные изменения и загружает удалённые. После одновременного редактирования исходная заметка получает серверный текст, а отдельная копия сохраняет локальную правку. Повторная синхронизация передаёт эту копию на остальные устройства.

### Запуск на своём компьютере

Понадобятся Node.js 24 и Git. Сервер и браузерный клиент используют только штатные API.

```sh
git clone https://github.com/zazzool/moroshka-notes.git
cd moroshka-notes
umask 077
printf 'MOROSHKA_TOKEN=%s\n' "$(openssl rand -hex 32)" > .env
node --env-file=.env server/app.mjs
```

Откройте `http://127.0.0.1:8090`. Значение `MOROSHKA_TOKEN` хранится в локальном `.env`. Генерация ключа нужна при первой установке. Повторный запуск использует тот же файл.

## Подключение компьютера с телефона

На подключённом Android-телефоне откройте меню библиотеки → «Подключить другое устройство». Передайте компьютеру показанный адрес сервера, например через системное меню «Поделиться». На компьютере откройте этот адрес в браузере и нажмите «Подключение». Введите восьмизначный код с экрана компьютера на телефоне и подтвердите. Браузер получит ключ и начнёт синхронизацию. Код действует две минуты, затем можно получить новый. Подключение сохраняется в браузере до очистки данных сайта. Не отправляйте код или ключ другим людям.

Для подключения по коду обновите сервер и приложение до версии с этой функцией.

## Развёртывание с Android

Подготовьте VPS с публичным IPv4-адресом или доменом, указывающим на сервер. SSH должен принимать пароль root на порту 22, а порты 80 и 443 должны быть доступны из интернета. Поддерживаются Ubuntu 22.04/24.04, Debian 12/13 на x86-64 или ARM64, а также системы с уже установленными Docker, Compose v2, curl и openssl.

В приложении выберите **«Подключить или развернуть сервер» → «Развернуть свой сервер»**, введите адрес и пароль root. Сверьте SSH-отпечаток с данными VPS-провайдера и подтвердите. Приложение передаст свой проверенный набор файлов, установит сервер, дождётся HTTPS и синхронизирует заметки. Пароль root не сохраняется. При обрыве связи установка продолжится на сервере. Повторный запуск использует тот же ключ и том с заметками.

Текущая серверная реализация использует Docker, Node.js и Caddy. В тестовой сборке образы приложения и Caddy занимают около 129 и 63 МБ соответственно до учёта общих слоёв. На тестовом хосте процессы приложения и Caddy в простое занимали около 65 и 44 МБ RSS без Docker. Потребление зависит от архитектуры и размера библиотеки. Это ограничение текущей версии при выборе очень малого VPS.

Для публичного IP используется сертификат Let's Encrypt с автоматическим продлением каждые несколько дней. Если адрес недоступен проверяющим серверам или порты закрыты, сертификат получить не удастся. На одном VPS перезапуск контейнеров помогает восстановиться после сбоя процесса. Сохранность при отказе диска или самого VPS требует отдельной резервной копии.

## Свой VPS

Альтернативный графический установщик **Moroshka-Server.pyz** входит в [предварительный релиз](https://github.com/zazzool/moroshka-notes/releases). На компьютере требуются Python 3.10+, Tk и OpenSSH (`ssh`, `ssh-keyscan`). На сервере установщик поддерживает чистую Ubuntu 24.04 или Linux с уже настроенными Docker и Compose v2, curl, openssl и flock.

1. Направьте DNS домена на VPS. Порты 80 и 443 должны быть свободны и доступны извне. Для установки нужен SSH на 22-м порту с правами root или беспарольным sudo.
2. Через доверенную консоль провайдера получите отпечаток командой `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`. Подготовьте свой SSH-ключ или загрузите его в ssh-agent.
3. Запустите `python3 Moroshka-Server.pyz`, укажите SSH-адрес, домен и SHA256-отпечаток. Нажмите **Развернуть или обновить**. После проверки HTTPS кнопка копирования выдаст ключ синхронизации для устройств.

Установщик отправляет на VPS исходники своей версии по SSH, собирает образ, подключает постоянный том и запускает Caddy с автоматическим HTTPS. Повторный запуск сохраняет том и ключ. После неудачной проверки при обновлении скрипт пытается вернуть предыдущий выпуск. Первичная настройка DNS и предоставление VPS выполняются владельцем.

## Выпуск из облака

| Задача | Команда или workflow |
| --- | --- |
| Проверить сервер | `node --test tests/*.test.mjs` |
| Проверить браузер | Python с Playwright и Chromium, затем `CHROMIUM=/usr/bin/chromium python3 tests/browser.py` |
| Собрать Android | JDK 17, Android SDK 35, Build Tools 35.0.0, затем `cd android && ./gradlew :app:assembleDebug :app:assembleRelease` |
| Собрать образ | `docker build -t moroshka:local .` |
| Упаковать установщик из текущего коммита | `python3 deploy/package-installer.py` |
| Выложить текущий коммит напрямую с облачного компьютера | `bash deploy/publish.sh user@vps.example.org notes.example.org` |
| Выложить из GitHub | Actions → **Deploy to my server** → **Run workflow**, ветка `main` |
| Опубликовать стабильный APK | Actions → **Release signed Android APK** → **Run workflow** |

На чистом облачном Linux x86_64 команда `bash deploy/cloud-android.sh` устанавливает проверенные по SHA-256 JDK и инструменты Android в локальный кэш `.cloud-tools/`, запускает Gradle Wrapper и сохраняет проверенный debug APK в `release/`. При первом запуске SDK предложит принять условия Google. Для подписи стабильной сборки укажите путь к защищённому файлу ключа в `MOROSHKA_KEYSTORE` и задайте через секреты окружения `ANDROID_KEY_ALIAS`, `ANDROID_STORE_PASSWORD`, `ANDROID_KEY_PASSWORD`. Скрипт создаст `release/Moroshka-Notes-release.apk`. Этот путь работает независимо от GitHub Actions.

Для прямой выкладки заранее сохраните проверенный SSH host key в `~/.ssh/known_hosts` и подключите ключ пользователя VPS. Для выкладки из Actions задайте в окружении `production` переменные `DEPLOY_TARGET`, `DOMAIN` и секреты `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`. Вторая переменная-секрет содержит строку known_hosts, сверенную с отпечатком провайдера. Выкладка отправляет исходники из Git без доступа VPS к приватному репозиторию. Команда проверяет внешний `/healthz` до активации версии.

Debug APK имеет отдельный идентификатор `app.moroshka.notes.debug`. Preview имеет отдельный идентификатор `app.moroshka.notes.preview` и подпись тестового ключа; он устанавливается параллельно предыдущим версиям с отдельным хранилищем. Не удаляйте старое приложение ради установки Preview. Публикация Preview выполняется после успешного CI (включая запуск Android-тестов на эмуляторе) для явно отмеченного `[preview-release]` коммита в `main`. Начиная с Alpha 10 публикация требует исходный ключ Preview в окружении `preview-release`: `PREVIEW_KEYSTORE_BASE64`, `PREVIEW_KEY_ALIAS`, `PREVIEW_STORE_PASSWORD`, `PREVIEW_KEY_PASSWORD`. CI проверяет совпадение сертификата последнего опубликованного Preview и увеличение versionCode. Если ключ утерян, нельзя безопасно обновить эту установку; не удаляйте её без проверенной копии. Обычные CI-артефакты подписаны временным тестовым ключом и не являются обновлениями. Для стабильного приложения `app.moroshka.notes` владелец создаёт постоянный ключ подписи. В окружении `android-release` используются секреты `ANDROID_KEYSTORE_BASE64`, `ANDROID_STORE_PASSWORD`, `ANDROID_KEY_PASSWORD`, `ANDROID_KEY_ALIAS`. Перед новым стабильным выпуском увеличьте `versionCode` и `versionName` в Android-проекте. Workflow подписывает APK, проверяет подпись и создаёт GitHub Release с тегом версии.

## Сохранение заметок на Android

На главном экране нажмите «Выбрать папку для сохранения заметок» и подтвердите папку в системном проводнике. Приложение копирует заметки в неё и сохраняет новые версии как отдельные Markdown-файлы. При переустановке вновь выберите ту же папку: приложение восстановит последнюю проверенную версию каждой заметки. Выбранную папку можно найти и открыть через файловый менеджер. Без выбора папки локальные заметки остаются в данных приложения и удаляются вместе с ним. Перед удалением убедитесь, что необходимые заметки сохранены в выбранной папке или синхронизированы с сервером.

Длительное нажатие на карточку позволяет удалить одну заметку. Пункт «Удалить заметки» в меню открывает выбор нескольких заметок. На сервере удалённые заметки хранятся в файлах с расширением `.deleted`. Если другая версия изменилась до удаления, синхронизация сохраняет её и показывает конфликт. Для распространения удаления обновите сервер и клиенты до актуальной версии, затем синхронизируйте устройства.

В редакторе кнопка «＋ Связь» вставляет ссылку на выбранную заметку. «Голос» запускает системное распознавание речи, если оно установлено. Кнопка «Место» добавляет вручную введённое или выбранное из недавних название в заголовок. Определение местоположения запускается по кнопке и требует разрешения Android. Доступность названия зависит от службы геокодирования устройства. Новая заметка получает заголовок по текущей дате и времени.

## Перенос всей библиотеки одним файлом

На Android откройте меню библиотеки → **Сохранить архив библиотеки**. В браузере раскройте **Резервные копии** → **Сохранить архив**. JSON-файл включает все активные сохранённые заметки, UUID и SHA-256 каждой записи; формат одинаковый на двух платформах. Его можно хранить независимо от приложения и переносить между устройствами без сервера.

Для восстановления выберите **Восстановить из архива**. Все записи проверяются перед импортом. Существующий текст никогда не заменяется; отличающаяся версия с тем же UUID добавляется отдельно. Повторный импорт того же архива не создаёт дубликатов. Восстановление не зависит от ключа подписи APK и не требует входа в сервер.

Архив не шифруется; не передавайте его посторонним. В него не включаются ключи, настройки, корзина, история правок или несохранённый черновик. Ограничения: до 32 МиБ и 10 000 заметок, 512 КиБ на заметку. Квота браузера может быть меньше: при нехватке места импорт останавливается с сообщением, уже добавленные и исходные заметки сохраняются. Повторите импорт после освобождения места. Для резервной копии сервера целиком используйте процедуру ниже.

## История редакций и корзина

Android сохраняет прежнюю уникальную редакцию Markdown до перезаписи файла. В меню открытой заметки выберите **История на устройстве**, затем редакцию и **Сохранить копию**. В меню библиотеки **Корзина на устройстве** показывает удалённые локальные заметки и архивированные конфликтные удаления. Восстановление всегда создаёт новую заметку с новым UUID; прежняя запись остаётся в истории/корзине. Текст оригинала не изменяется.

На обновлённом сервере прежние синхронизированные редакции сохраняются в `history/<uuid>/<sha256>.md` внутри того же тома. В веб-редакторе **История сервера** позволяет посмотреть и скопировать их; **В корзину сервера** удаляет только подтверждённую синхронизированную редакцию. **Корзина сервера** позволяет посмотреть удалённые заметки и их историю. Восстановленная копия появляется в браузере локально и отправляется на сервер при следующей синхронизации.

История начинается с установки новой версии; ранее перезаписанные данные нельзя восстановить из неё. История Android локальная, серверная — только для принятых сервером редакций. Это не покадровый журнал правок: одинаковый текст хранится один раз. Несинхронизированные старые редакции браузера не архивируются. История и корзина пока не имеют автоматической очистки, могут занимать дополнительное место, не включаются в переносимый JSON-архив и должны учитываться при резервном копировании. Удаление приложения уничтожает локальную историю, если она не сохранена отдельно.

## Автоматическая синхронизация

Автообмен выключен по умолчанию и не меняет ручной режим. После подключения сервера включите **Автосинхронизация в фоне** в библиотеке Android или **Автосинхронизация** в боковой панели веб-клиента.

- Android: системный JobScheduler запускает обмен после выхода из приложения (минимальная задержка 5 секунд) и периодически, с интервалом 30 минут. Нужны доступная сеть, достаточно заряда и свободного места. Задания сохраняются после перезагрузки; фактическое время определяет Android. При возвращении в приложение фоновой операции запрещаются дальнейшие локальные изменения, а экран перечитывает сохранённые данные. Ручной обмен и автоматический обмен не выполняются параллельно.
- Веб: обмен планируется через 3 секунды после сохранённых изменений, при восстановлении соединения и периодически (120 секунд) в видимой вкладке. При недоступном сервере задержка увеличивается до 5 минут. Редактор доступен во время сетевого запроса; если пользователь изменил текст после отправки, новая правка остаётся локальной и будет передана следующим обменом. Если сервер изменил или удалил открытую заметку, применение этой редакции откладывается до закрытия редактора. Конфликты сохраняются отдельными заметками.
- Браузер не синхронизируется после закрытия вкладки. Android может отложить работу из-за Doze, ограничений производителя или принудительной остановки приложения. На обновлённом сервере используется инкрементальная передача текстов; со старым сервером сохраняется полный снимок. Настройку можно выключить в любой момент; уже переданный серверу запрос нельзя отозвать.

## Инкрементальная синхронизация

При каждом обмене обновлённый клиент запрашивает список UUID и SHA-256 текущих и удалённых заметок. Текст запрашивается только для отсутствующих на устройстве или изменённых на сервере редакций, пакетами до 8 заметок. Локальные правки передаются прежними условными PUT/DELETE; совпадение контрольных сумм позволяет пропускать неизменённые тексты. Если запись меняется между получением списка и загрузкой текста, сервер возвращает 409 и клиент повторяет обмен позднее, не подставляя текст другой редакции.

Миграция Markdown-файлов не требуется: новый сервер поддерживает старый полный API, новые клиенты используют его при ответе 404 от эндпоинта списка ревизий. Ошибки авторизации, сети и конфликтов не приводят к откату на полный API. Первая синхронизация всё ещё загружает все отсутствующие заметки, а полный список ревизий передаётся при каждом обмене. Сервер перечитывает файлы для расчёта контрольных сумм; журнал изменений с курсором и дисковый индекс остаются дальнейшими оптимизациями. Подробнее: [протокол](docs/incremental-sync.md).

## Хранилище и резервные копии

Каждая заметка — UTF-8 файл `<uuid>.md`. Заголовок берётся из строки `# Название`. UUID сохраняется при редактировании. Вики-ссылки используют текст заголовка. Переименование заголовка пока требует обновить ссылающиеся заметки. Запись через API опирается на SHA-256 прочитанной версии и атомарную замену файла. Один серверный процесс обслуживает один каталог. Владельцу стоит остановить запись через приложение на время массовой правки файлов на диске.

Сервер хранит Markdown в Docker-томе `moroshka_notes`, настройки интеграций и ключи — в `/etc/moroshka/keys.env`. Для резервной копии с согласованным состоянием остановите сервис приложения, сохраните содержимое тома и отдельно зашифрованную копию файла ключей, затем запустите приложение. Старые версии приложения доступны под `/opt/moroshka/releases/<идентификатор>/`.

## Интеллектуальная библиотека

После синхронизации заметки откройте **Предложения ИИ** в Android или Web. Модель OpenRouter возвращает предложения заголовка, типа (заметка/задача/идея/проект/материал) и тегов. Подтвердите нужные поля или отклоните всё. Ответ привязан к исходной SHA-256-редакции; при изменении заметки повторите анализ. Принятие меняет только заголовок и добавляет выбранные теги (тип хранится как `#type-idea` и аналогичные); исходный текст не заменяется пересказом. Автоматическая отправка текста при сохранении отключена: анализ запускается по запросу.

**Смысловой поиск и связи.** В `/etc/moroshka/keys.env` настройте `OPENROUTER_EMBEDDING_MODEL` (совместимая embedding-модель OpenRouter) и ключ. Перезапустите сервер. В разделе «Смысловой поиск» последовательно индексируйте пакеты до 8 заметок, явно разрешая передачу текста. Затем запросите поиск по смыслу. На открытой индексированной заметке «Смысловые связи» предлагает реальные заметки из того же актуального индекса. Ссылка добавляется только после подтверждения, неоднозначные заголовки отклоняются.

Индекс хранится на вашем сервере, в том же томе, и привязан к модели и точной редакции. Изменённые или удалённые заметки исключаются из результатов до переиндексации. Передаётся не более первых 12 000 символов на заметку; длинные заметки могут индексироваться неполно. Запросы к внешнему ИИ могут быть платными. Индекс можно удалить из интерфейса, сами заметки сохранятся; это не удаляет ранее переданные провайдеру данные.

**MCP.** Задайте отдельный случайный `MCP_TOKEN` (от 24 символов, отличный от ключей синхронизации и Actions). После перезапуска подключите клиент, поддерживающий Streamable HTTP и пользовательский Bearer-заголовок, к `https://ваш-домен/mcp`. Доступны `list_notes`, `search_notes` и `read_note`, только для чтения активной библиотеки. Поддерживаются протоколы 2026-07-28 и legacy 2025-11-25/2025-06-18/2025-03-26. Нет OAuth, автоматического добавления приложения в каталог ChatGPT или права на запись. Ключ даёт чтение всей активной библиотеки; не публикуйте его. MCP проверяет Host и Origin: при заданном PUBLIC_URL используйте его канонический адрес; без PUBLIC_URL допустимы только loopback-hosts.

Подробнее о настройке, границах и проверках: [Интеллектуальная библиотека](docs/intelligent-knowledge.md).

## Интеграции

**OpenRouter.** В `/etc/moroshka/keys.env` задайте `OPENROUTER_API_KEY` и `OPENROUTER_MODEL` (идентификатор доступной вашему аккаунту модели). После изменения параметров выполните на VPS `cd /opt/moroshka/current && sudo docker compose up -d --force-recreate app`. В веб-редакторе синхронизируйте заметку и нажмите **Резюме в OpenRouter**. После подтверждения сервер передаст первые 12 000 Unicode-символов именно этой ревизии. Все обращения к OpenRouter запрашивают `data_collection: deny` и `zdr: true`; при отсутствии подходящего провайдера запрос завершится ошибкой, а не ослаблением требований. Это ограничения маршрутизации, не независимая гарантия соблюдения политики провайдерами. Ключ остаётся на VPS. Не отправляйте неанонимизированные конфиденциальные данные. [API OpenRouter](https://openrouter.ai/docs/api-reference/chat-completion)

**Приложение ChatGPT.** Для постоянного поиска по библиотеке создайте закрытый пользовательский GPT с Actions в аккаунте, которому доступно создание GPT. Задайте отдельный случайный `ACTIONS_TOKEN` длиной от 24 символов, перезапустите сервис приложения и импортируйте схему `https://ваш-домен/openapi.json` в редактор Actions. В Authentication выберите **API Key → Bearer** и укажите этот ключ. Установщик задаёт `PUBLIC_URL` автоматически. В созданном GPT запросите поиск заметки по слову и чтение найденного ID. Доступ ограничен поиском и чтением, ключ даёт доступ ко всей библиотеке. Для разовой передачи одной заметки доступно системное меню Android. [Аутентификация GPT Actions](https://developers.openai.com/api/docs/actions/authentication)

## Границы первой версии

Одна библиотека рассчитана на одного владельца. Сервер видит содержимое файлов и защищает транспорт через HTTPS. Синхронизация запускается вручную или автоматически по явной настройке и передаёт только отсутствующие или изменившиеся тексты при поддержке инкрементального API. Предел заметки — 512 КиБ, объём браузерной копии зависит от квоты браузера. В этой версии есть список задач, поиск и связи. Идеи и следующие этапы описаны в [обзоре продукта](docs/product.md).
