# Moroshka Notes

Личная библиотека Markdown для Android и браузера. Напишите мысль, добавьте `[[Название]]` и откройте ссылку, чтобы создать следующую заметку. В разделе связей появится обратный путь. Строки `- [ ]` собираются в общий список задач. Поиск работает по тексту, заголовкам и `#тегам`.

## Попробовать

- **Android 8+**. Скачайте тестовый APK из [релизов](https://github.com/zazzool/moroshka-notes/releases). Заметки сохраняются в приватном каталоге приложения. Импорт и экспорт отдельных файлов доступны через системный выбор документов. Меню «Поделиться» передаёт выбранный текст в другое приложение.
- **Браузер**. Откройте адрес своего сервера или запустите сервер на компьютере. Редактор сохраняет изменения в хранилище этого браузера. После первого открытия по HTTPS или через localhost оболочка кэшируется для офлайн-работы. Очистка данных сайта удаляет локальную копию. Для переноса используйте синхронизацию или экспорт.
- **Обмен между устройствами**. Введите адрес сервера и ключ на Android. В браузере введите ключ через «Подключение». Кнопка «Синхронизировать» отправляет локальные изменения и загружает удалённые. После одновременного редактирования исходная заметка получает серверный текст, а отдельная копия сохраняет локальную правку. Повторная синхронизация передаёт эту копию на остальные устройства.

### Запуск на своём компьютере

Понадобятся Node.js 24 и Git. Сервер и браузерный клиент используют только штатные API.

```sh
git clone https://github.com/zazzool/moroshka-notes.git
cd moroshka-notes
umask 077
printf 'MOROSHKA_TOKEN=%s\n' "$(openssl rand -hex 32)" > .env
node --env-file=.env server/app.mjs
```

Откройте `http://127.0.0.1:8090`. Значение `MOROSHKA_TOKEN` хранится в локальном `.env`. Генерация ключа нужна при первой установке. Повторный запуск использует тот же файл.

## Свой VPS

Графический установщик **Moroshka-Server.pyz** входит в [предварительный релиз](https://github.com/zazzool/moroshka-notes/releases). На компьютере требуются Python 3.10+, Tk и OpenSSH (`ssh`, `ssh-keyscan`). На сервере установщик поддерживает чистую Ubuntu 24.04 или Linux с уже настроенными Docker и Compose v2, curl, openssl и flock.

1. Направьте DNS домена на VPS. Порты 80 и 443 должны быть свободны и доступны извне. Для установки нужен SSH на 22-м порту с правами root или беспарольным sudo.
2. Через доверенную консоль провайдера получите отпечаток командой `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`. Подготовьте свой SSH-ключ или загрузите его в ssh-agent.
3. Запустите `python3 Moroshka-Server.pyz`, укажите SSH-адрес, домен и SHA256-отпечаток. Нажмите **Развернуть или обновить**. После проверки HTTPS кнопка копирования выдаст ключ синхронизации для устройств.

Установщик отправляет на VPS исходники своей версии по SSH, собирает образ, подключает постоянный том и запускает Caddy с автоматическим HTTPS. Повторный запуск сохраняет том и ключ. После неудачной проверки при обновлении скрипт пытается вернуть предыдущий выпуск. Первичная настройка DNS и предоставление VPS выполняются владельцем.

## Выпуск из облака

| Задача | Команда или workflow |
| --- | --- |
| Проверить сервер | `node --test tests/*.test.mjs` |
| Проверить браузер | Python с Playwright и Chromium, затем `CHROMIUM=/usr/bin/chromium python3 tests/browser.py` |
| Собрать Android | JDK 17, Android SDK 35, Build Tools 35.0.0, затем `cd android && ./gradlew :app:assembleDebug :app:assembleRelease` |
| Собрать образ | `docker build -t moroshka:local .` |
| Упаковать установщик из текущего коммита | `python3 deploy/package-installer.py` |
| Выложить текущий коммит напрямую с облачного компьютера | `bash deploy/publish.sh user@vps.example.org notes.example.org` |
| Выложить из GitHub | Actions → **Deploy to my server** → **Run workflow**, ветка `main` |
| Опубликовать стабильный APK | Actions → **Release signed Android APK** → **Run workflow** |

На чистом облачном Linux x86_64 команда `bash deploy/cloud-android.sh` устанавливает проверенные по SHA-256 JDK и инструменты Android в локальный кэш `.cloud-tools/`, запускает Gradle Wrapper и сохраняет проверенный debug APK в `release/`. При первом запуске SDK предложит принять условия Google. Для подписи стабильной сборки укажите путь к защищённому файлу ключа в `MOROSHKA_KEYSTORE` и задайте через секреты окружения `ANDROID_KEY_ALIAS`, `ANDROID_STORE_PASSWORD`, `ANDROID_KEY_PASSWORD`. Скрипт создаст `release/Moroshka-Notes-release.apk`. Этот путь работает независимо от GitHub Actions.

Для прямой выкладки заранее сохраните проверенный SSH host key в `~/.ssh/known_hosts` и подключите ключ пользователя VPS. Для выкладки из Actions задайте в окружении `production` переменные `DEPLOY_TARGET`, `DOMAIN` и секреты `DEPLOY_SSH_KEY`, `DEPLOY_KNOWN_HOSTS`. Вторая переменная-секрет содержит строку known_hosts, сверенную с отпечатком провайдера. Выкладка отправляет исходники из Git без доступа VPS к приватному репозиторию. Команда проверяет внешний `/healthz` до активации версии.

Debug APK имеет отдельный идентификатор `app.moroshka.notes.debug`. Для стабильного приложения `app.moroshka.notes` владелец создаёт постоянный ключ подписи. В окружении `android-release` используются секреты `ANDROID_KEYSTORE_BASE64`, `ANDROID_STORE_PASSWORD`, `ANDROID_KEY_PASSWORD`, `ANDROID_KEY_ALIAS`. Перед новым стабильным выпуском увеличьте `versionCode` и `versionName` в Android-проекте. Workflow подписывает APK, проверяет подпись и создаёт GitHub Release с тегом версии.

## Хранилище и резервные копии

Каждая заметка — UTF-8 файл `<uuid>.md`. Заголовок берётся из строки `# Название`. UUID сохраняется при редактировании. Вики-ссылки используют текст заголовка. Переименование заголовка пока требует обновить ссылающиеся заметки. Запись через API опирается на SHA-256 прочитанной версии и атомарную замену файла. Один серверный процесс обслуживает один каталог. Владельцу стоит остановить запись через приложение на время массовой правки файлов на диске.

Сервер хранит Markdown в Docker-томе `moroshka_notes`, настройки интеграций и ключи — в `/etc/moroshka/keys.env`. Для резервной копии с согласованным состоянием остановите сервис приложения, сохраните содержимое тома и отдельно зашифрованную копию файла ключей, затем запустите приложение. Старые версии приложения доступны под `/opt/moroshka/releases/<commit>/`.

## Интеграции

**OpenRouter.** В `/etc/moroshka/keys.env` задайте `OPENROUTER_API_KEY` и `OPENROUTER_MODEL` (идентификатор доступной вашему аккаунту модели). После изменения параметров выполните на VPS `cd /opt/moroshka/current && sudo docker compose up -d --force-recreate app`. В веб-редакторе синхронизируйте заметку и нажмите **Резюме в OpenRouter**. После подтверждения сервер передаст текст именно этой ревизии. Ключ остаётся на VPS. [API OpenRouter](https://openrouter.ai/docs/api-reference/chat-completion)

**Приложение ChatGPT.** Для постоянного поиска по библиотеке создайте закрытый пользовательский GPT с Actions в аккаунте, которому доступно создание GPT. Задайте отдельный случайный `ACTIONS_TOKEN` длиной от 24 символов, перезапустите сервис приложения и импортируйте схему `https://ваш-домен/openapi.json` в редактор Actions. В Authentication выберите **API Key → Bearer** и укажите этот ключ. Установщик задаёт `PUBLIC_URL` автоматически. В созданном GPT запросите поиск заметки по слову и чтение найденного ID. Доступ ограничен поиском и чтением, ключ даёт доступ ко всей библиотеке. Для разовой передачи одной заметки доступно системное меню Android. [Аутентификация GPT Actions](https://developers.openai.com/api/docs/actions/authentication)

## Границы первой версии

Одна библиотека рассчитана на одного владельца. Сервер видит содержимое файлов и защищает транспорт через HTTPS. Синхронизация запускается вручную и получает снимок библиотеки целиком. Предел заметки — 512 КиБ, объём браузерной копии зависит от квоты браузера. В этой версии есть список задач, поиск и связи. Идеи и следующие этапы описаны в [обзоре продукта](docs/product.md).
