# Capture-first UX / Alpha 11

Primary action: persistent bottom composer, not a decorative home hero. The main feed is chronological with body-first excerpt, timestamp, secondary title and compact contextual metadata. Android touch targets remain at least 48dp. Secondary actions remain available without taking space from capture. Existing design assets remain in the repository; unused decorative imagery no longer occupies home/list screens.

Photos: immutable JPEG (2400px longest side, <=2MiB), separate content-addressed storage. Markdown reference lines are hidden from the editing field and rendered as photo attachments; removing one attachment never deletes its bytes from history. Media upload precedes note upload, and missing remote images are verified before local application. Archive v2 includes exact referenced bytes and SHA-256; v1 remains readable. SAF copies separate JPEGs. Full volume backups preserve history and media. Photos are resized/re-encoded, not lossless originals. Derived/orphaned media is retained; garbage collection is a separate task. Date in the feed is last modification, not original creation; legacy browser entries without time remain unknown until synced.

OCR uses a configured OpenRouter image-capable model via explicit consent and strict privacy routing, not an on-device OCR engine. Preview/edit before adding transcript. Actual recognition quality is provider-dependent. No automatic transfer to an external model. Camera availability and file picker behavior depend on OS/browser; emulator tests cover image processing, local editing and archive, not a physical camera or paid model.

References: [Android primary actions and navigation](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns), [Android camera intents](https://developer.android.com/guide/components/intents-common), [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Basic_Terminology), [OpenRouter image inputs](https://openrouter.ai/blog/tutorials/send-image-to-llm/).

## Final capture polish

Mobile web places secondary library controls in a compact “Ещё” disclosure. Exchange remains accessible without opening the menu. Saving from any view returns to the unfiltered notes feed. A photo import captures the original draft at the start and does not erase subsequent typing. Recognition is accessible directly from the editor, and an individual photo note can be exported as a portable archive including its bytes. Android reuses the initial local inventory during synchronization instead of rescanning the whole vault for each remote metadata row. CI captures actual light/dark mobile feed and editor screenshots and checks the header/capture geometry.
